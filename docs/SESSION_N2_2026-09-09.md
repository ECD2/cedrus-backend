## What landed

### A3.1 — token verification in code, MFA required

- `src/services/auth/jwt.js` — decodes and verifies a Supabase JWS with `node:crypto`:
  ES256 (what the Cedrus project signs with today), RS256, HS256. Signature first, then
  `exp`/`nbf`, `iss`, `aud`, `role = authenticated`, UUID `sub`. `alg: none` and everything
  else is `unsupported_alg`. HS256 never reads a JWK as a secret (no algorithm confusion).
  Every refusal is a short category; no result carries the token.
- `src/services/auth/keys.js` — the JWKS source: `<SUPABASE_URL>/auth/v1/.well-known/jwks.json`,
  fetched lazily, cached 10 min, refreshed once early on an unknown `kid` (rate-limited to one
  per minute so random kids cannot make the server loop). A fetch failure is `key_unavailable`
  → the choke point answers **500, not 401** (an outage must never read as a bad login).
- `src/services/auth/verifier.js` — `createTokenVerifier({ hmacSecret, jwks, issuer, now })`
  (the DI form the suite uses) and `createSupabaseTokenVerifier({ env, fetch, now })` (the
  production form; HS256 only if `SUPABASE_JWT_SECRET` is set — optional, the project is ES256).
- `src/services/auth/assurance.js` — the policy: `aal` must be `aal2`. `aal1` → `aal2_required`;
  a missing claim → `aal_missing`; anything else → `aal_unknown`. All refused.
- `src/routes/api/auth.js` — `createRequireUser` (the single choke point every /api router
  mounts) now: parses the bearer → if it is a JWT, verifies it locally → applies the assurance
  policy (**401 `mfa_required`** with a reason) → looks up `app_users` by `auth_user_id = sub`
  → `account_status` must be active (403, unchanged, proof A6) → `req.appUser`, `req.authUserId`,
  `req.authSession { aal, methods, issued_at, expires_at, session_id }`.
  Identity still comes from the token and never from the request (A3, unchanged).
  The previous `auth.getUser(token)` delegation survives ONLY as the **non-JWT seam**: a bearer
  that does not parse as a JWT (the opaque `tok-a` tokens the pre-A3.1 suites use with a fake
  GoTrue) is handed to `auth.getUser`. It is refused outright in production (`reason: malformed`),
  announced once in the log elsewhere, and GoTrue itself parses every bearer as a JWT, so it
  can never authenticate anyone against a real project. A real JWT never takes it.
- The verifier announces its mode on first use (`web.auth.verifier`: JWKS host, HS256 on/off,
  issuer, required assurance) — Lesson 7.

### A3.2 — `/api/interface`, the per-person read API

`src/routes/api/interface.js`, mounted in `src/index.js` **before** the authed `/api` catch-all
(two lines: the import and the mount). Every route sits behind the choke point above. No handler
reads a user id from body, query, path or header. The person's CoS scope comes from THEIR
`user_settings.cos_user_id` (`src/services/auth/callerScope.js`, explicit `.eq('user_id', appUser.id)`)
— never from `COS_USER_ID`/`COS_BRIEF_USAGE_USER_ID`. Every CoS read goes through `forUser()`.

| Route | Returns | When it cannot |
|---|---|---|
| `GET /session` | `user` (id, name, display_name, timezone, role), `session` (aal, methods, issued_at, expires_at, session_id), `capabilities` (the four closed-vocabulary booleans; absent row = false), `preferences.skin` = **null slot** | 503 `capabilities_unreadable` on a failed read (never "all false") |
| `GET /status` | per-service state: `brief` (user_settings + the per-user send ledger via `alreadySentToday`), `cos` (linked/armed), `programs` (`todays_program_items` count), `sms` (phone, consent, opt-out, capability), `agents` (capability, last CoS agent run) | 503 `settings_unreadable`/`capabilities_unreadable`; per-service `unreadable` state with the error code |
| `GET /brief/today` | the stored `today_brief_v1` row the daily job wrote back (`structured_output`, incl. `workspace_state` and `todays_program`) if its `generated_at` is today **in the person's timezone** | `available:false` with `cos_not_linked` / `cos_disarmed` / `not_generated_today` (+ `latest_generated_at`); 503 `brief_unreadable` on a failed read |
| `GET /workspace` | `workstreams`, `open_loops`, `decisions` in the reader's own projections (`READER_COLUMNS`), plus the reader's caps | `available:false` `cos_not_linked` / `cos_disarmed`; 503 `workspace_unreadable` |

Shapes: `src/routes/api/interface.shapes.d.ts` (TypeScript). Every field is a column, a claim, or a
function the Engine already has. `preferences.skin` is declared as a slot typed `null` because
`user_settings` has no such column; the adapter must not persist it. A3.3 reconciles with the
adapter shapes the parallel session reports.

`/brief/today` reads `today_briefs` with exactly `READER_COLUMNS.today_briefs + structured_output +
expires_at`. The two extra names are keys of the row `writer.js` inserts (Bundle 47 pins the list
to those two sources, Lesson 20). It reads `generation_mode='ai'` and `status='ok'` — the same
selection CoS's own `latestStoredBrief()` makes, plus the status filter because an error row has
nothing to show.

### Proof — Bundle 47, `test/auth-api.test.mjs` (136 PASS, 0 FAIL)

Real router over node:http; real verifier against a throwaway HS256 secret AND a P-256 pair
generated in-process (the ES256 path production uses); real CoS client + reader over HTTP to a
PostgREST double in the test that honours `col=eq.v`, `order`, `limit`, `select`. Controls on
every refusal; a SELF-CHECK that the double returns everyone's rows unfiltered.

- aal1 → 401 `mfa_required` (`aal2_required`); the SAME claims at aal2 → 200. A payload rewritten to
  aal2 under an aal1 signature → `bad_signature`, so the claim cannot be forged.
- Two users, two tokens: each `/workspace` returns only its owner's rows AND its own rows (non-empty);
  the wire request for each carried `user_id=eq.<its own CoS id>`.
- Suspended with a valid aal2 token → 403 on every route; `'banana'` → 403; active control → 200.
- Forged `user_id` / `cos_user_id` / `auth_user_id` in the query and `x-user-id` headers → ignored.
- Expired / bad signature / wrong issuer / service_role JWT → 401 with a category; the body never
  contains the token or a segment of it.
- ES256 through the real choke point → 200; a different key pair → `bad_signature`; unknown kid →
  `unknown_key`; JWKS unreachable → `key_unavailable` (500).
- The non-JWT seam: 200 outside production (control), 401 `malformed` in production.
- Failed reads are 503s, never empty 200s (capabilities, settings, workspace, brief); an unreadable
  program read is reported as `unreadable` with its code.
- Pins: the vocabulary equals the migration's CHECK list (parsed from the SQL); the brief columns ⊆
  reader ∪ writer; every response key is declared in the shapes file; `/api/interface` is mounted
  before the `/api` catch-all.
