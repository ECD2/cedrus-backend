## The contract, as written

Exactly the approved columns — no `created_at`/`updated_at` on `programs` or `program_items`, because the contract names ten and twenty columns respectively and the migration's ASSERT 1 compares the sorted column lists by name and refuses anything else. `scheduled_date`, `start_date`, `end_date` are `date`; ASSERT 1 reads `information_schema` and refuses a timestamp.

What the schema enforces beyond the column list:

- `user_id` on every table → `app_users(id)`, plus **composite FKs** `(program_id, user_id) → programs(id, user_id)` and `(program_revision_id, user_id) → program_revisions(id, user_id)`: an item or revision cannot belong to a different person than its program. Proven with a smuggled insert (23503).
- `UNIQUE (program_id, source_sha256)`, `UNIQUE (program_id, revision_number)`, `UNIQUE (program_revision_id, item_key)`.
- CHECKs: `kind`, `status` ×2, `category` (the twelve-name union, verbatim), `planned_start_local` as HH:MM, positive durations, `end_date >= start_date`, sha as 64 hex.
- RLS enabled and forced on all three; three SELECT-own policies to `authenticated`; `authenticated` holds SELECT only; `anon` holds nothing.

`publish_program_revision(owner, kind, title, description, start, end, tz, source_name, source_text, items jsonb)` finds or creates the program by (owner, kind, title) — created programs are `active` — computes the SHA-256 of the stored text in SQL, writes the revision with `supersedes_revision_id = current_revision_id`, writes every item at `planned` with NULL actuals (the function has no way to write an actual), asserts every item is inside the program's dates, moves `current_revision_id`, and asserts its own post-conditions. Same source again → the UNIQUE raises 23505 and the function re-raises it naming the existing revision. No pre-check anywhere: the constraint is the authority.

`todays_program_items(owner, at)` returns one owner's items from each active program's current revision where `scheduled_date = (at at time zone program.time_zone)::date`. Owner NULL → nothing.
