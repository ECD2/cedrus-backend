## What the job actually emits — read from the code, not from the handoff

The handoff said the verifier should report "a cos.brief.aborted line with its reason field". The line has no such field. This table is what the three emit sites hand the logger and what survives the allowlist onto the line:

| Event | Emit site | Structured fields on the line | Only in the message |
|---|---|---|---|
| `cos.brief.aborted` | `cosDailyBrief.js` — unresolved owner | `error_category="config"`, `outcome="fail_closed"` | the owner source: `cannot determine whose brief to compose (unresolved) — …` |
| `cos.brief.aborted` | `cosDailyBrief.js` — gather `read_failed` | `error_category="db_error"`, `outcome="fail_closed"` | the tables: `CoS tables unreadable (a, b) — …` |
| `cos.brief.aborted` | `cosDailyBrief.js` — program read failed (Law 11 tripwire) | `error_category="db_error"`, `outcome="fail_closed"`, `error_code="42883"` (or `PGRST202`) | the table: `program_items unreadable (CODE: detail) — …` |
| `cos.brief.written` | `writer.js:232` | `outcome="ok"` | the owner source: `brief written back to CoS today_briefs (owner id source: X)` |
| `programs.today.read` | `cosDailyBrief.js` | `outcome="items"\|"none"`, `count=N`, `reason="settings"\|"env"` | — |
| `programs.today.skipped` | `cosDailyBrief.js` | `outcome="no_app_user"` | — |

Three things follow, and the verifier is built on them:

- **`reason` is in the allowlist, and none of the three abort sites passes it.** So the verifier prints the fields the line carries, under their own names — `error_category=db_error outcome=fail_closed error_code=42883` — and never a `reason:` it would have to invent. The suite pins this with a control: the parsed abort line has `fields.reason === undefined`.
- **Table names and the owner source are prose-only, on purpose.** The allowlist keeps free-form text out of structured fields, and a table name is free-form text. The verifier reads them from the message in the three exact shapes the job writes. The `program_items` parenthetical is an *error*, not a table list — a comma split would report `42883: function todays_program_items(uuid` as a table — so that branch names the table from the word before `unreadable` and leaves the detail to `error_code` and the errors section.
- **`count` and `reason` on `programs.today.read` are structured.** Both were already in the allowlist when the event was written, so, unlike `cos.email.truncated` in August, no prose fallback is needed and none was added. `reason` there is the *block's* owner-id source (`resolveProgramOwner`: rows first, env second), a different lookup from the one on the written line; the two can disagree and the report prints them separately.

Also found while reading: the verifier's header said `cos.owner.derived` sits between `cos.send.ok` and `cos.brief.written` "on every real run in the dumps". II.5 recorded on 2026-09-04 that this describes the August dumps only — the event has not fired since `COS_USER_ID` was set on 2026-08-30. The header now says so.

- Does not add a prose fallback for the programs count (the fields are on the line) and does not decide whether a `settings` label is true.
- Does not add fixture files, a bundle number, a dependency, a harness edit, or a canon edit.
